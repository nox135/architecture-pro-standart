### <a name="_qmphm5d6rvi3"></a>**Решение**

[Context](c4_context.puml)

[Container](c4_container.puml)

[Задачи](epics.md)

[RoadMap](RM_bank_standart.drawio.png)

Решение построено на принципах гибкости и минимального вмешательства в существующие процессы. Для обеспечения обратной
совместимости и работы с партнерскими системами, не имеющими API, выбран механизм обмена данными через SFTP.

Внутренний сервис будет с заданной периодичностью опрашивать Сервис управления депозитными
ставками (Rate Service) на предмет наличия обновлений. При обнаружении изменений Rate Service формирует актуальный файл
с данными, который SFTP-сервис забирает и передает на сервер партнера. Это гарантирует своевременное обновление
информации в партнерском кол-центре без необходимости с его стороны модернизировать свою инфраструктуру, а также
минимизировать количество ресурсов для проведения обновлений.

Таким образом, процесс синхронизации является управляемым со стороны банка, не требует автоматизации на стороне партнера
и обеспечивает надежную доставку данных даже при временной недоступности внешних систем.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

Прямая интеграции систем партнерских кол-центров по API для передачи актуальных ставок в режиме реального времени.

Преимущества:

Полностью исключается ручной труд и задержки, связанные с файловыми обменами.

Отпадает необходимость в использовании поддержке SFTP.

Данные в системах партнеров всегда абсолютно актуальны.

### Недостатки, ограничения и риски:

Политика информационной безопасности: Предоставление доступа к API во внешний контур требует сложной и длительной
процедуры согласования с отделом ИБ и мониторинга.

Недостатки и риски: Будет задержка в передаче данных, которая при частых изменениях может привести к неактуальным данным
и
ошибкам при общении с клиентом
